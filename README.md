# kiln

A WebAssembly runtime in Rust with no dependencies. It decodes the binary format, instantiates modules (memory, table, globals, element and data segments, start function) and runs them in an interpreter. It's checked against V8, the engine inside Node. Random valid programs have to give exactly the same results, traps and memory contents in both, and broken modules have to be rejected the same way.

The long-term goal is a runtime that runs real compiled software (SQLite, Lua, a C compiler built with clang or Rust for wasm32-wasi) with full validation, WASI, and the post-MVP features. It should be fast enough to be within 2x of V8, which means a compiler to native code, not just an interpreter. Today it's the MVP interpreter, with the gaps measured.

## Build and run

Needs Rust (stable, no crates), Python 3 (standard library) and Node 22 or newer for the comparison.

```
cargo build --release
cargo test --release
./target/release/kiln gen 42 /tmp/m.wasm /tmp/m.calls     # a random valid program and its calls
./target/release/kiln calls /tmp/m.wasm /tmp/m.calls
node tools/run.mjs calls /tmp                             # the same calls under V8
./target/release/kiln examples /tmp && ./target/release/kiln bench /tmp/fib.wasm fib i32:30
python3 tools/check.py                                    # everything above, compared
python3 tools/mutants.py                                  # plants bugs, reports what catches each
```

## How the comparison works

`kiln gen SEED` writes a module with one page of memory, some globals and a chain of functions, where each function can only call earlier ones so nothing recurses. Expressions are generated by type, so every module is valid. They use every MVP numeric op, the sign-extension and saturating-truncation ops, loads and stores of every width, blocks with early exits, if/else, bounded loops, select, calls and memory.grow. Division by zero, overflow, bad float-to-int conversions and out-of-bounds accesses all happen, so traps are compared too. After every call the `checksum` export hashes all of memory.

NaN payloads and signs aren't deterministic in WebAssembly. V8 on x86 and Rust on ARM give different bits for 0/0, and both are correct. So the generator canonicalises any float whose bits become observable: before a reinterpret, before a store, and before the sign operand of copysign. Results compare NaNs as just "nan".

`tools/run.mjs` runs the same call scripts in Node and prints results in kiln's format. Trap messages are mapped to kiln's categories: div-zero, overflow, oob, bad-conversion, unreachable, indirect, stack. V8 reports a NaN and an out-of-range float-to-int conversion with the same message, so kiln puts both in bad-conversion.

## Known gaps

These are measured. They are the roadmap.

1. **No validator.** The decoder checks that the binary is well formed and that indices are in range, so kiln never crashes on garbage. But it never type-checks function bodies. With one or two random bytes flipped in the 300 test modules, V8 rejects 219 of them and kiln accepts 19.2% of those. It also rejects 2 that V8 accepts.
2. **Slow.** It's a plain interpreter over decoded ops, with u64 value slots, a label stack and a Vec of locals per call. It's 36x to 115x slower than V8, 55x geometric mean. Calls are the worst case.
3. **MVP only.** It doesn't support imports, so there's no WASI and no host functions. It also lacks multi-value, bulk memory, reference types, SIMD and tail calls. V8 accepts all six feature probes in check.py, and kiln rejects all six.
4. **The generator misses things.** `tools/mutants.py` plants 15 bugs and 12 are caught. These three survive:
   - `i32.load8_s` zero-extending
   - `f32.min(0, -0)` returning +0
   - `memory.grow` ignoring the declared maximum

   The random programs rarely load bytes above 0x7F, compare signed zeros through min, or grow memory twice.

## Layout

```
src/module.rs    binary decoder: sections, LEB128, constant expressions, function bodies to Ops
src/exec.rs      instance and interpreter, traps, float semantics
src/build.rs     encoder used by the generator and the examples
src/gen.rs       random valid programs
src/examples.rs  benchmark programs (fib, sieve, collatz)
tools/run.mjs    runs the same calls under V8
tools/check.py   the comparison
tools/mutants.py planted bugs
```
